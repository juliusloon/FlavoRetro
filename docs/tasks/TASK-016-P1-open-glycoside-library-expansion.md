## P2：批量反应准入、计数与开发分组

## P3：模板适用范围和结构表示规则

1. 对实际生成的新 O/C/糖间键验证方向/中心、完整参与物、立体和催化上下文，来源的多步路径只有在原文能定位独立单步时才准入。
2. 同时保留 exact_instance_template 与 scope_template。后者以来源支持的共同中心、受体结构条件、糖型/供体及酶/催化上下文声明作用范围；生成器通过这些约束作用于未登记的精确目标，不能只是把 holdout 目标补进 allowed_targets。
3. 至少 4 个 scope_template 各有来自 build 的至少 2 个不同受体支持实例，证明其声明范围跨越一个精确产物；允许有限插值，不自动称跨骨架泛化。至少 2 个不同糖型，以及位点/错误供体/立体/越界母核/错误上下文中相关边界必须有对照。
4. 每个可执行模板对全部声明支持实例精确重现 100%，任何失败留在原分母并阻止该模板准入；至少 2 项边界对照全部符合声明，违反数 0。
5. neutral/ionic_equivalence 仅定义可解释的酸碱质子化表示关系，另存规则版本与实际改变原子；不跨不同共价结构、异构体、糖型、同位素或盐/计量。原始严格签名与规则下匹配分别报告，单纯表示命中增加不计为新的成键反应/新底物补回。
6. 支持实例与至少一个来源支持的中性/离子态表示对照重放；未知质子化/必要对离子或质子化导致不适用的情况保留 unknown，不能无条件中和。
