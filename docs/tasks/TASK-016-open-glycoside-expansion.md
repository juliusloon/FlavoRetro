## 目标

通过公开 API 或官方可程序化下载入口，自主获取、整理黄酮苷相关反应；从结构明确、来源可追溯的实例构建适用范围受限的逆合成模板，作为独立领域策略接入现有 MCTS，测量能否补回基础模型在冻结设置下未提出的候选步骤。

首要问题是新糖苷键形成步骤的候选生成覆盖，分别报告 O-糖苷、C-糖苷与糖—糖连接；保护/脱保护、原有糖苷修饰及水解等支持步骤单列。第一版不以调高现有动作分数或全面搜索调参替代反应能力补充。化学合成与酶催化均可纳入，不预设类别配额；由实际来源质量与覆盖决定首批模板。

完整工程交付要求至少一条有开放来源支持的成键主类模板能生成合格动作并进入真实 MCTS；只有支持步骤可用时如实交付 Partial。工程通过与覆盖增益分别判定：补回数为零可报告工程完成，但不能宣称覆盖提升。

## 必须执行的操作与阶段门槛

### G1：开放来源冻结与实例合同

1. 先记录当前工作区 execution-baseline.json，校验上述依赖/载荷与审核加载，并冻结来源清单、查询条件、下载/解析范围、版本、取得时间、文件大小和 SHA-256。分别登记 metadata_only、raw_available、parsed、unavailable、parse_failed，不用一个 success 覆盖全部状态。
2. 最小实例字段包含 provider/dataset/version/record_id、原始定位与哈希、许可、DOI/专利/PMID/实例位置、原始与规范化反应物/产物、条件及收率的归属/缺失、催化模式、解析与审核身份。
3. 每条原记录均保留处置和原因；零值、真实负结果、缺失、冲突、解析失败、通式及多步路径分别标记。没有转化证据的零/失败实验不作为正向模板种子。
4. 保留来源记录、具体实验、精确反应、变换/反应中心的独立计数与关联；条件重复不扩增模板数，重复出处不抬高独立证据量。主集合按形成 O/C/糖—糖新连接分类，次集合按已有糖苷修饰、保护/脱保护、水解等分类；无法确定方向/中心的记录保留 uncertain。
5. 首批工程默认上限：新增原件下载 5 GiB、最多 4 个采集工作进程，单服务按官方限制降低并发；已有冻结原件可只读复用。取得清单后在预算内细化并记录，不以填满预算为目标。

### G2：基础模型缺口诊断

1. 在查看基础/增强覆盖结果前，按来源质量、变换类型与固定 record/group ID 顺序冻结开发实例/目标选择规则和分母；抽样顺序与数量不按模型成败选取。模型缺口是测量结果，不能只选基础模型失败样本充当总体评测集。冻结模型/模板/配置哈希、候选截断、过滤和单步预算。
2. 分别记录模板覆盖未知/不适用、候选生成、截断、过滤、生成失败及实际进入搜索的状态；不能把“冻结设置下未观察到”无条件解释成“模型绝对不会生成”。
3. 区分糖苷键真正变化、原有连接保留的其他步骤和仅有分子拓扑命中。无可靠反应中心时标 uncertain，不把 uncertain 当负例。
4. 冻结 reference_precursor_set 和匹配规范：以来源明确的角色/参与物定义所需前体，记录所有纳入/未纳入组分及理由，不在看结果后删去难匹配的供体、盐或其他参与物。比较清除 atom-map 后的 isomeric canonical SMILES 组分多重集合，保留方向、立体、同位素、盐与重复组分；不以名称、家族、子结构或相似度代替精确匹配。与现有审核索引的完整实例签名匹配另列，不能混成一个分数。
5. 保存生成、截断后、过滤后及 MCTS 实际创建动作的逐层观察和所用 outcome index。基础生成成功但未匹配才属于可判定缺口；基础生成错误/超时留在冻结分母，不能计为“模型确实缺该步”。

### G3：受限模板构建

1. 从结构明确、反应中心可解释且有来源依据的具体记录建立模板。机器映射/抽取记录工具、版本与失败，不能标 human_reviewed。
2. 每个模板登记来源实例、结构变换、适用/排除条件、催化类别、供体/受体/酶/辅因子约束、立体处理、验证状态和未知项。
3. 具体来源支持与数据库整理状态分别保留；通式知识条目可作线索，不能假扮具有已核对实验条件的实例。需要猜补反应物、方向或结构的记录不进入可执行模板集合。
4. 实例重现须实际应用逆合成模板并比较前体，而非断键后连回原图。为每个可执行模板保留支持实例和相关错误对照；同源实例重现仅证明计算实现与来源表示一致。
5. 迁移到其他结构的结果单列为生成候选。未经对应证据确认，不能把迁移命中写为化学正确或可实验执行。主类模板必须由来源支持的正向成键转化导出相应逆合成动作；不能从水解记录的机械倒转声称成键反应已获验证。
6. 每个可执行模板冻结至少一个支持实例及一个与声明适用边界相关的错误对照（如错误位点/糖型、越界底物或禁止的源上下文），记录预期和实际。对声明可重现的全部实例，前体精确重现率须 100%；错误对照必须无违反所声明边界的接受。其他真实来源未验证的邻近结构保留 unknown，不充当已确认化学负例。

### G4：独立策略接入

1. 领域模板通过独立开关加载，与通用策略并存，复用现有审核关联/父子进程绑定和结果链路。动作保存 template_id、source_instance_id、催化模式、模板/来源版本与当前审核绑定，贯穿请求、候选、运行清单和结果。新增来源使用独立 TASK-016 命名空间和不可变版本，不覆盖 TASK-015 视图。
2. 分别保存 template_source_support（模板种子出处支持）、exact_instance_match（当前生成反应严格匹配具体实例）、prediction_conditions_verified（当前预测条件确认状态）。迁移到新底物或旧索引 unmatched 时，只保留实际存在的证据，不继承支持实例的产率或验证身份。既有 ReviewedEvidence 注释不能覆盖/丢失新模板来源；未知不是化学否决。
3. 冻结候选合并/去重、领域候选上限和权重；第一版不按开发成绩反复调权重。处理模板生成多 outcome 的原始 index，保留失败与预算开销。
4. 明确领域动作的验证与过滤路径，记录被哪个检查接受/拒绝；不得为得到正结果静默放宽过滤、全局绕过既有检查或让酶促动作因默认规则被无记录丢弃。

6. G1—G3 的可执行集合与配置冻结通过后才运行真实 MCTS。独立加载该集合不改变活动 v3，也不改变 evidence_closed、actionable 或 production 的科学含义。

### G5：开发对照与限域报告

1. 主要对照：A=当前 optimized MCTS + task015-06-v1 adjudicated 审核 + 固定库存 + 领域策略关闭；B=A 的全部基线 + 领域策略开启。冻结相同模型、过滤、结构规则、目标/种子、时间/迭代/节点限制。不能以 legacy_validation 作为主对照，也不能把审核接管或库存变化记成模板增益。

## 指标定义、分母与判定

G2 的 development_contract.json 冻结来源/实例组、目标、主/次集合、参考前体、结构匹配规范、候选/过滤阶段、种子、预算、配置/代码/模板/审核哈希，以及下面各项的统计单位。开始比较后不修改这些字段；需要修订时保留原版本、说明原因，新结果单列。

N 为主集合中按精确反应去重的冻结参考实例组数；同一反应多个来源/条件不增加 N。N_gap 为其中基础单步执行正常、过滤后未精确匹配的组数；基础错误/超时计入 N 但不计入可判定缺口 N_gap。支持步骤使用独立的 N_support。M 为主目标面板预登记的目标 × seed 配对数，支持目标面板另用 M_support，各配对均保留 A/B 结果；目标与 seed 的从属关系明确。主/次目标面板互斥，同一目标同时有主/次参考时归主面板，支持参考另表且不增加运行次数；相同目标的多个参考实例共享一次候选/运行观察，不增加独立目标数。

| 指标 | 定义与统计单位 | 必须报告/验收要求 |
| --- | --- | --- |
| 原记录处置对账 | 每条取得的原记录恰有一个最终处置，全部处置数之和等于取得范围内原记录数 | 差额=0；未扫描范围与取得失败单列，不能把抽样写成全源覆盖 |
| 来源/模板/动作追溯完整率 | 已准入实例、模板、实际领域动作分别具有完整来源 ID、定位、原件/版本哈希及实际证据状态的比例 | 三层均 100%；无来源或关键结构/方向不明者不进入可执行集合 |
| 模板实例重现率 | 精确重现的声明支持实例数 / 模板声明支持实例总数 | 每个可执行模板 100%，失败不得移出声明分母；模板边界错误对照违反数=0 |
| 过滤后覆盖 C_A / C_B | 对每个冻结实例组单步诊断中，至少一个过滤后动作精确匹配参考前体的组数 / N | 分别报告 x/N；失败/超时在 N 中且不给命中。生成前/截断后其他阶段分别列数 |
| 可判定缺口补回 G / N_gap | A 正常执行且未匹配、B 正常执行且匹配的主集合组数 G / N_gap | 同时报 G 的绝对数；N_gap=0 时率为 null 并说明，不填 0% 或 100%；基础错误改善另列 |
| 覆盖净变化与损失 | 净变化=100×(B 命中组数−A 命中组数)/N，单位为百分点；损失为 A 已命中而 B 未命中的组数 | 正/负/零均报告，B 失败导致损失单列；N=0 时覆盖未估计，不能用支持步骤替代 |
| 新增精确候选动作 | 同一目标、同一阶段，B 动作签名集合减 A 集合；签名含完整目标与实际 outcome 的前体结构多重集合及方向；原始 outcome index 保留在追溯字段，不作跨模板去重键，不以 template ID 计数 | 重复模板、同一动作多个来源合为动作组，同时保留所有来源；主/次类分别计数 |
| MCTS 实际补回与进入率 | 每个 target×seed 配对保存 matched_action_created 的 A/B；扩展补回数为 A 正常未创建、B 正常创建参考动作的配对数 / M | 单独报告完整目标数、3 个 seed 的逐次结果和配对数；创建动作须有真实节点/动作记录，不能用生成器输出或最终路线条数替代 |
| 失败/超时/未知 | 对 N 的诊断状态、M 对的每组运行状态及所有记录/动作的未知理由分别计数 | 各自分母明确；unknown 不作化学负例，失败/超时不删除、不挑最优 seed |
| 运行成本与候选负担 | 每次实际时间、节点、迭代、模型/领域候选数、模板尝试数、生成/过滤时间与 A/B 配对差 | 包含失败/超时开销；节点/候选与 run ledger 可对账；计时覆盖全部 phase |
| 路线与闭合状态 | 每个 target×seed 的 partial / surrogate / evidence_closed、不同路线数和实际参考步骤匹配 | 次要开发观察；17 库存固定、精确供应仍无认证，不作为候选覆盖的唯一成功标准 |

允许声明“成键候选覆盖提升”的最低证据是 G≥1，且对应 A/B 正常诊断、来源、参考前体与动作日志可核对；同时报告损失和净变化。若净变化≤0，不声称总体开发覆盖改善。声明真实搜索补回另须至少一个主集合参考动作由 B 在真实 MCTS 创建而同配对 A 未创建。单个实例/配对的正结果不构成普遍化学有效性或算法优越性。

对首批来源不预设反应数/模板数增长率、O/C/酶促配额或正增益门槛；有用来源不足时报告零值/短缺。过程完整、至少一条主类模板实际接入但 G=0，可工程 Completed 并明确“未观察到成键覆盖增益”；只有支持步骤或无法接入主类模板则 Partial，按停止条件保存可核查产物。
