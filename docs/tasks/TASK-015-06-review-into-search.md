### 分轴和关联规则

- 最小审核对象：record_id + 具体结构/反应签名 + 来源定位/哈希 + 审核版本。保留 structure_classification、primary_source、yield、note_locator、identity、current_vendor、record_disposition 等独立轴及各自审核者类型。
- identity-final-51 使用 record_id/ref；vendor-final-49 使用 stock_ref；name-decisions 使用 FGM ID。构建器须按对应字段建立显式 crosswalk，核对原始定位、结构及哈希，不能假定各文件都用 id，更不能只按名称或 CID 连接。
- 库存身份以完整结构和 InChIKey 校验；实际准入逐记录审计，再合并同结构键并保留所有有效/隔离出处。冲突记录不贡献身份/供应声明；若有另一个独立有效同图记录，不因共享键无差别隔离。
- 反应签名按正向角色归一：逆合成动作的前体为 reactant、被展开分子为 product。使用固定 RDKit 2023.09.6 的去 atom-map 标号、isomeric canonical SMILES、两侧组分多重集合；保留立体、同位素、盐、组分重复及多产物，排序不去重、不额外中和/去盐/互变异构归并。
- 多 outcome 使用实际原 index；完整记录的两侧均相符才 exact_match。仅产物、子结构、家族、名称、模糊相似或笔记关键词命中只能为 partial/context，不能贡献原文/产率正面声明。
- 多产物原文、组分角色不明、缺项或无法表达的实例，记录 ambiguous/not_applicable/unmatched；不截出一个产物补造单步支持。可以得到 0 个严格来源匹配，此结果不阻断如实交付。
- P4 来源黑名单及 P3 排除撤销该来源/记录的正面支持资格；不能由「来源撤稿/领域不相关」推导所有相同模型动作化学错误。仅凭证据不足不拒绝通用模型动作、不提高或降低其 prior。
- 同结构匹配不意味着条件相同；参考实例的条件/产率以 source_instance_* 字段展示，不写作本次预测条件/预计收率。不把 >99% 化成严格100、不把38覆盖38.11、不丢弃91.9±5.2的HPLC方法和不确定度；零、缺失与冲突各自保留。
