# ADR-006：方法交付与独立评价分阶段结项

- 状态：accepted
- 日期：2026-10-13
- 负责人：项目所有者；Cano记录决定。
- 批准溯源：agent_delegated，human_reviewed=false；所有者本会话明确同意“TASK-016 按已交付的模板、搜索接入及有限开发效果结项；将 C/SS 的正式独立迁移检验明确写入 TASK-017”，并指示编制TASK-017。
- 决定记录：operations/task017-draft-20261013/scope_decision.json。

## 背景

原TASK-016及P1已经完成来源支持的模板、独立领域策略接入及有限开发覆盖。P6交付合格v6与旧能力保护；C/SS新目标科学矩阵未完成。P7以更严格fresh面板追求双轴开发迁移，在2026-10-13正式Partial/stopped；P9确认已有历史目标的开发价值，同时识别同范围留组支持集中与闭包缺口。

若继续将P7效果门当作全部TASK-016方法交付结项前置，会把已交付的方法、独立评价准备、正增益主张混成一个状态。原论文主线已将正式独立评测分配给TASK-017；需要明确各阶段应交付的证据。

## 决定

1. TASK-016阶段按已交付的开放数据、来源/范围受限成键模板、受控搜索接入、局部开发效果与保护证据结项。结项不扩大O/C/SS泛化、化学可行性或供应主张。
2. C/SS的正式独立新目标迁移检验在TASK-017明确承担，独立标签、来源/assay隔离、冻结协议、真实MCTS及既有formal前置继续保留。
3. 评价任务以有效实验完成为验收；正/零/负结果如实交付。正迁移能力另设effect_pass，不能要求先证明正增益才允许正式测量。
4. P7保持原Partial/stopped、epochs关闭、fresh0及metrics=null；旧TASK/REPORT/账和曝光不修改。原P7效果门继续描述其历史科学目标，不再决定TASK-016方法交付是否结项。不是追认P7科学通过。
5. P9保留原规划Completed及未运行状态；历史材料可用于开发，不能通过改任务编号变成独立盲测。
6. “写TASK-017”授权合同编制和本次阶段分工登记；其实际实施、科学读取和正式运行仍需明确执行批准和实际准入通过。当前release/preflight无变化。

## 备选方案

- 继续以P7正迁移门阻挡方法阶段结项：保持单一门，但掩盖已交付资产并容易继续恢复循环，未采用。
- 把全部历史C/SS对象直接称为独立评价或把P7改Completed：会破坏曝光、隔离和历史真实性，未采用。
- 分开方法交付、正式评价完成、正迁移主张：能继承成果并保留未解决科学问题，采用。

## 影响与风险

当前STATE、Roadmap、索引以本决定登记阶段职责；历史TASK/REPORT仍按当时合同解释，不回写科学结果。TASK-017可开展独立设计/准入准备，不因本决定自动获执行批准或formal_run_ready。

TASK-017仍可能因独立标签、干净来源、供应/资源投影或其他实际前置不满足而停止；阶段分工不能制造评价数据。已有有限开发效果不能作为新目标或全空间性能证明。

## 复审条件

若拟改变独立评价来源、标签责任、正式准入或方法主张范围，应以新合同/明确修订记录复审。若TASK-017发现方法/结构缺陷，另立开发修复任务并保留原评价，不在已见test上补调方法。本决定不解除具名内容停止和旧epoch锁。
