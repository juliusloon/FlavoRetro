# ADR-007：科研评价准备、科研运行与供应发布资格分离

- 状态：accepted
- 日期：2026-10-13（Asia/Shanghai）
- 负责人：项目所有者；Cano记录。
- 批准溯源：所有者针对具体准入拆分方案明确指示“修订。”；agent_delegated，human_reviewed=false。
- 批准与范围记录：outputs/evaluation/task017-v02-revision-20261013/revision_decision.json。
- 对应合同：[TASK-017 v0.2](../tasks/TASK-017-independent-c-ss-transfer-benchmark.md)。

## 背景

v0.1真实G0检查在工程资产通过后被全局来源/供应、独立标签/协议和production投影全部阻断。供应与production要求回答资源认证问题，却被用作方法迁移测量的前置；独立panel和标签又是TASK-017应准备的产物，不能要求在任务准备开始前全部存在。这个责任混合会使评价准备无法推进，不能据此推断方法效果或来源穷尽。

## 决定

1. preparation_ready用于允许有界准备：实际执行授权/合同/预算可追溯，方法/资产可冻结，合法来源和角色隔离/交接安排可落实。无需已有gold、最低panel或供应/production认证。
2. research_run_ready用于正式科研矩阵：方法、代码/模型/配置/审核/17候选库存、实际最低panel、独立标签、逐项一手参考、来源/曝光闭包、协议及预算全部绑定并通过真实检查。缺失或无效必需证据不能放行，未检查记null。
3. 方法支持血缘与评价参考逐项核验继续必要；不要求全库模板/库存先人工晋级production。影响独立性或参考正确性的unknown仍阻断对象；通用模型训练重叠unknown按原范围披露。
4. 当前供应证据和production投影保留各自真实资格规则，不作为本轮方法迁移测量前置。研究完成/正增益不得宣称采购可用、实验可行、production或发布就绪。
5. 拟新增任务范围科研检查及运行前强制核验；旧evaluation.preflight和formal_run_ready的CLI/API与兼容语义保持。科研放行不翻转旧门或release_ready，不靠metadata字段或目录存在替代底层核验。
6. 局部协议审核绑定实际协议/合同版本、SHA、批准者权限、范围、时间与依据。合同准入设计批准、独立标签核验和最终panel/执行协议冻结分别登记，执行授权不等于上述事实已完成。
7. v0.1全部G0事实和REPORT只读保留；后续实际执行用新的v2事实源。预算累计而不重置。P7、旧epochs、曝光、科学指标及TASK-016阶段结项不改变。

本决定细化ADR-006第2/6项及影响段中的“既有formal前置”，不修改ADR-006阶段分工和P7终止。PAPER_ROADMAP的旧“供应/production先齐备再动工”统一前置由本决定取代；历史段落按其当时合同解释。

## 备选方案

- 继续统一供应/production门：能保留原代码路径，但把科研测量变成认证任务，未采用。
- 直接把release元数据写为approved或删除全部检查：没有真实标签/参考/隔离依据，未采用。
- 按准备、科研运行和资源资格分别真实核验：采用，要求增加局部检查与范围明确的结果展示。

## 影响与风险

TASK-017可以先落实自身负责的面板/标签准备与合成工程核验；没有保证会得到合格最低面板或正迁移。独立标签职责仍须由真实角色落实，不能靠更换agent/任务编号洗掉曝光。合同修订本身不产生科研门通过结果。

本轮只有文档修订；科研检查、执行器和测试待实现，preparation_ready=research_run_ready=null，正式矩阵未运行。metadata/release.json及旧代码保持不变。后续实现须证明供应/production未认证不会阻断合格科研证据，同时缺标签/闭包/协议或SHA漂移仍阻断，并保留旧CLI/API行为。

## 复审条件

若拟改变最低panel、标签授权、独立性、方法/参数、统计分母、预算、供应/发布主张或旧接口语义，须明确修订并保留原记录。若test影响方法，依原规则排除/另立开发任务，不能用本决定放行。
